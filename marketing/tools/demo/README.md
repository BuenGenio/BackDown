# The docs' live demo (`public/demo/`)

The guides embed BackDown's own web UI, running in the reader's browser on an invented set of drives. It is the
real `crates/backdown-cli/ui/`, byte for byte but for its paths, answered not by a BackDown but by the Cloudflare
Worker (`src/demo.js`) from responses recorded here against a real BackDown fed with invented data. Nothing in it
is anyone's data, and nothing can be changed: a POST the recording never saw gets a polite refusal.

## What's in the demo

Six "drives" of one fictional person, Alex, and a NAS, generated by `gen.py` (deterministic, ~70 MB on disk,
~14 GB on paper: videos, installers and panoramas are sparse files):

| Drive | Path in the demo | What's on it |
|---|---|---|
| Old Laptop | `/media/alex/Old Laptop` | a Linux home folder: photos of four trips with GPS, music, videos, a Maildir, a git repository with `node_modules`, documents of every kind the viewers open (PDF, docx, xlsx, pptx, odt, csv…), a downloads pile |
| Backup 2021 | `/media/alex/Backup 2021` | a Time Machine set (three snapshots), an rsync copy of the laptop from 2020 with a newer snapshot of the same mailbox, an iPhone backup, a Nextcloud data folder, MySQL dumps, a WordPress site, an mbox export; the drive's health is *failing* |
| Camera cards | `/media/alex/Camera cards` | DCIM dumps: originals of two trips that exist elsewhere, and Kyoto photos that exist nowhere else |
| Archive | `/media/alex/Archive` | what `backdown plan` + `apply --go` filed from the three drives above (so the chain of custody has 4 K events) |
| Mirror | `/media/alex/Mirror` | `backdown mirror` of the archive's media, synced and verified |
| nas (`/volume1`, `/volume2`) | another machine, reached "over ssh" | its own index: a music and photo library, videos, rsync backups, and a pool folder |

Drive health and the list of disks come from `BACKDOWN_FAKE_HEALTH` and `BACKDOWN_FAKE_VOLUMES` (JSON files,
templates here with `@D@` for the demo's folder); the machine calls itself `alex-desktop` through
`BACKDOWN_HOSTNAME`. These three hooks exist in the binary for tests and demos and change nothing else.

## How it's made

```
cargo build --release -p backdown-cli      # a binary with the hooks above (1.0.0-beta.10 or later)
cd marketing/tools/demo && npm install     # puppeteer-core; Firefox at /usr/bin/firefox (or FIREFOX=…)
./run.sh                                   # everything below, into $DEMO_HOME (default /tmp/backdown-demo)
```

Step by step (`. env.sh` first; it points every BackDown at the demo's own data folder, never yours):

1. `python3 -I gen.py "$D"` writes the drives.
2. `./seed.sh` indexes them twice (the second scan with edits, so folders have versions), hashes, recognises,
   reads the photos' dates and places, signs two manifests, adds the NAS (the `shim/ssh` runs the NAS's end of
   BackDown locally against its own index), plans and applies the archive, syncs and verifies a mirror.
3. `./daemon.sh start` runs the demo's daemon on port 8798 (`token`, `url`, `log`, `stop`).
4. `node record.mjs "$BASE" "$TOKEN" "$D/rec"` drives the UI in headless Firefox through every view, opens
   viewers, searches, ticks drives in Wipe, and crawls every folder listing and the photos' thumbnails directly,
   recording every `/api/` response.
5. `node bundle.mjs "$BASE" "$TOKEN" "$D/rec"` writes `public/demo/`: the UI with `/api/` → `/demo/api/` and
   `/vendor/` → `/demo/vendor/`, `demo.js` in front of it, and `d/<sha1(key)>` per response with
   `d/index.json` mapping keys to status, type and file. Every path of this machine is rewritten to Alex's
   (`/media/alex/…`, `/home/alex/…`), including the base64 folder keys the app puts in URLs.
6. `python3 build.py` renders the docs; a `<figure class="demo" data-view="places" data-caption="…"></figure>`
   block becomes the frame (`data-dir` opens a folder, `data-mode` a layout, `data-tab` a tab inside the view).
   `figures.py` holds where each guide's frames go and re-places them in both languages.

`node preview.mjs` serves `public/` locally with the Worker's demo route, for checking before `wrangler deploy`.

## How it works at request time

`src/demo-keys.js` turns a request into a key (method, path, sorted query without the long-poll parameters);
`src/demo.js` looks it up in `d/index.json`, falling back to the same path without a query, then to a per-path
fallback (an unknown search gets the recorded empty result; a missing `/api/content` gets `placeholder.svg`).
`demo.js` in the page shows the banner, opens the view or folder the docs asked for, and offers the full window.
